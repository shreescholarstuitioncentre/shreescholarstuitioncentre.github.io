1. What is Programming?

A computer cannot think; it only follows instructions. A program is a set of instructions written in a programming language. Programming is the process of planning, writing, testing and maintaining programs, and the person who does it is a programmer.

HighC, C++, Java, Python, BASICEnglish-like, portable

Programs written by a programmer (source code) are converted to machine code by a compiler, interpreter or assembler.

3. Algorithm

An algorithm is a finite, step-by-step method to solve a problem. Characteristics: finiteness, definiteness, input, output, effectiveness.

Example: larger of two numbers

Step 1: Start
Step 2: Read A, B
Step 3: If A > B then print A
Step 4: Else print B
Step 5: Stop

4. Pseudocode

Pseudocode is an English-like outline of the logic, not tied to any language.

INPUT A, B
IF A > B THEN
    PRINT A
ELSE
    PRINT B
ENDIF

5. Flowchart

A flowchart draws an algorithm with standard symbols joined by arrows (top to bottom, left to right).

8. Variables, Constants and Data Types

A variable is a named memory location whose value can change (e.g. sum). A constant never changes (π = 3.14). Data types: integer (12), float (3.5), character ('A'), string ("Hi"), boolean (True/False).

10. Solved Examples (step by step)

Easy 1: Write an algorithm to add two numbers. Test with 12 and 8.

Step 1: Start. Step 2: Read A, B. Step 3: Sum = A + B. Step 4: Print Sum. Step 5: Stop.
Test: A = 12, B = 8 → Sum = 12 + 8 = 20 ✓.

Easy 2: Algorithm for area and perimeter of a rectangle; l = 15, b = 8.

Read l, b → Area = l × b → Perimeter = 2 × (l + b) → Print both.
Area = 15 × 8 = 120; Perimeter = 2 × (15 + 8) = 2 × 23 = 46.

Intermediate 1: Draw the flowchart to find the larger of two numbers A and B (animated below) and trace A = 45, B = 72.

Trace: Read A = 45, B = 72 → is 45 > 72? No → follow the No arrow → Print B = 72 → Stop.

Intermediate 2: Flowchart to check even or odd; test N = 37.

Trace: 37 mod 2 = remainder 1 (since 37 = 2 × 18 + 1). Condition 1 = 0 is false → No → Odd.

Intermediate 3: Find the sum of the first 5 natural numbers by dry run, then verify by formula.

Algorithm: sum = 0; for i = 1 to 5: sum = sum + i; print sum.
isum = sum + isum
10 + 11
21 + 23
33 + 36
46 + 410
510 + 515
Final sum = 15.
Formula check: n(n+1)/2 = 5 × 6 / 2 = 15 ✓.

Intermediate 4: Algorithm to find 5! (factorial).

fact = 1; for i = 1 to 5: fact = fact × i.
i=1 → 1; i=2 → 2; i=3 → 6; i=4 → 24; i=5 → 120. Check: 5×4×3×2×1 = 120 ✓.

Hard 1: Find the greatest of 45, 72 and 58 using an algorithm, counting comparisons.

Max = 45 (first number).
Compare 72 with Max: 72 > 45 → Max = 72 (comparison 1).
Compare 58 with Max: 58 > 72? No → Max stays 72 (comparison 2).
Answer: 72, with 2 comparisons = 3 − 1.

Hard 2: Prove that finding the maximum of n numbers needs n − 1 comparisons. Find for n = 10.

Start: n candidates for the maximum. Each comparison rules out exactly one number (the smaller). To be left with 1 candidate we must rule out n − 1 numbers, so n − 1 comparisons are needed. Hence proved.
For n = 10: 9 comparisons.

Hard 3: Algorithm to test whether 29 and 91 are prime.

Divide N by every i from 2 up to √N; if any divides exactly, N is not prime.
N = 29: √29 ≈ 5.38, test 2, 3, 4, 5 → remainders 1, 2, 1, 4 → none is 0 → 29 is prime.
N = 91: √91 ≈ 9.5, test 2…: 91 mod 2 = 1, 91 mod 3 = 1, 91 mod 5 = 1, 91 mod 7 = 0 → stop → 91 = 7 × 13 is not prime.

Hard 4: Find Celsius to Fahrenheit for 37 °C using F = C × 9/5 + 32 and verify by reversing.

F = 37 × 9 / 5 + 32 = 333 / 5 + 32 = 66.6 + 32 = 98.6 °F.
Verify: C = (98.6 − 32) × 5 / 9 = 66.6 × 5 / 9 = 333 / 9 = 37 ✓.

Hard 5: Euclid's algorithm: find GCD of 48 and 18 and count the steps.

Repeat: replace (a, b) by (b, a mod b) until b = 0.
(48, 18): 48 mod 18 = 12 → (18, 12)
(18, 12): 18 mod 12 = 6 → (12, 6)
(12, 6): 12 mod 6 = 0 → (6, 0) stop.
GCD = 6 in 3 steps. Check: 48 = 6×8, 18 = 6×3, and 8, 3 have no common factor ✓.

Hard 6: Classify the error: (a) print(“Hi” with missing bracket (b) area = l + b (c) avg = total / n when n = 0.

(a) Syntax error – grammar broken, caught before running.
(b) Logical error – runs but wrong result (should be l × b).
(c) Runtime error – division by zero while running.

11. Short Q & A (tap for answer)

Q1. What is a program?

A set of instructions written in a programming language to make the computer do a task.

Q2. What is programming?

The process of designing, writing, testing and maintaining programs.

Q3. Who is a programmer?

A person who writes programs.

Q4. What is an algorithm?

A finite, step-by-step set of instructions to solve a problem.

Q5. Write the characteristics of a good algorithm.

Finiteness (ends), definiteness (clear steps), input, output, effectiveness (doable steps).

Q6. What is a flowchart?

Q7. Which symbol is used for decision?

Diamond (rhombus).

Q8. Which symbol is used for input/output?

Parallelogram.

Q9. Which symbol shows start and stop?

Q10. What is pseudocode?

An informal, English-like description of an algorithm, not tied to any language.

Q11. Algorithm vs flowchart?

Algorithm is in words; flowchart is the same logic drawn with symbols.

Q12. What is a variable?

A named memory location whose value can change.

Q13. What is a constant?

A value that does not change during the program, e.g. π = 3.14.

Q14. Name data types.

Integer (whole), float (decimal), character, string, boolean.

Q15. What is source code?

The program text written by the programmer.

Q16. What is debugging?

Finding and removing errors (bugs) from a program.

Q17. What is a bug?

An error in a program.

Q18. Name the three types of errors.

Syntax, logical and runtime errors.

Q19. What is a syntax error?

A violation of the language's grammar rules.

Q20. What is a logical error?

A mistake in the logic: program runs but the result is wrong.

Q21. What is a runtime error?

An error that occurs during execution, e.g. divide by zero.

Q22. What is structured programming?

Programming with sequence, selection and iteration only, in clear blocks.

Q23. What is modular programming?

Dividing a program into small independent modules (functions).

Q24. What is top-down design?

Breaking a big problem into smaller sub-problems step by step.

Q25. What is documentation?

Written explanation of the program: comments, user manual.

12. Long Q & A

Q1. Explain the steps of program development with diagram.

1) Define the problem. 2) Analyse inputs, processing and outputs. 3) Design the solution with algorithm/flowchart. 4) Code in a language. 5) Test and debug. 6) Document. 7) Maintain and update (see animated cycle).

Q2. What is an algorithm? Write an algorithm to find the average of three numbers.

Algorithm: Step 1 Start. Step 2 Read A, B, C. Step 3 Sum = A + B + C. Step 4 Avg = Sum ÷ 3. Step 5 Print Avg. Step 6 Stop. Example: 10, 20, 30 → Sum 60 → Avg 20.

Q3. Explain flowchart symbols. Why are flowcharts useful?

Oval = start/stop, parallelogram = input/output, rectangle = process, diamond = decision, circle = connector, arrow = flow. Useful because they make logic visual, easy to check, help find errors early and serve as documentation.

Q4. Explain the three control structures.

Sequence: statements run in order. Selection: a condition picks one path (if–else). Iteration: statements repeat while a condition holds (for, while). Any program can be built from these three (see animated chart).

Q5. Explain types of errors with examples.

See the table: syntax (grammar broken, found by translator), logical (wrong logic, wrong answer), runtime (crash while running).

Q6. Compare top-down and bottom-up programming.

Top-down starts from the whole problem and divides it into modules; easy planning and testing of parts. Bottom-up first builds small reusable routines and joins them into the full system. Real projects mix both.
